# F-Droid TV and Android Distribution Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking. Execution method awaits user selection; native execution is recommended because packaging, JNI generations, host installation and publication share interfaces.

**Goal:** Publish four editions from one source release, with small offline-capable F-Droid TV/phone APKs, an optional verified full collection and automated F-Droid recipe synchronization.

**Architecture:** Keep GitHub builds and the canonical full core AAR as the default. Generate a deterministic starter asset tree and official archive for F-Droid; use a separate official-library generation alongside the existing custom library. Source-set selection removes the real APK updater from F-Droid, while release metadata drives both build recipes and their GitLab synchronization.

**Tech Stack:** Java/framework Android Views, GLES 3/JNI/C++17, Gradle/AGP 8.12.0, Python standard library, fdroidserver 2.4.5, existing MkDocs/GitHub Actions tooling.

**Spec:** `docs/superpowers/specs/2026-10-11-fdroid-distribution-design.md`, approved 2026-10-11; candidate identities are in `docs/superpowers/specs/2026-10-11-fdroid-starter-candidates.json`.

## Global Constraints

- Preserve TV `nl.neerdael.projectmtv` and Android `nl.neerdael.projectm`; no distribution ID suffix.
- Preserve default TV tasks/output paths, `-PandroidTouchscreen=true`, existing GitHub stable APK names and the single `projectM-TV-core.aar` alias.
- `projectmDistribution=github|fdroid` defaults to `github`; reject other values. No renderer repairs, AndroidX, corpus rescoring or routine changes to the `2.3.0`/49/`8b70620339018cfaf5ac05acdb4ea8104dc2eb59` version-floor triple.
- All four release APKs use the same source SHA and release name/code. Published GitHub APKs and the canonical core retain 9,606 presets and 74 textures; F-Droid APKs contain exactly 20 qualified starters and only necessary textures/index rows.
- Keep TV audio/remote behavior and phone microphone/playback/touch/consent behavior. Respect GL-thread ownership and native reader retirement.
- GitHub updater defaults to On only when no value is stored; explicit Off survives. F-Droid excludes the real APK updater, provider registration and install permission.
- Use the approved prompt labels, equal access to decline, no request before download consent, and Settings download/cancel/retry/remove actions.
- Build/download libraries deterministically from repository assets. Trust the descriptor bundled with the APK, keep official/custom stores separate and retain a usable library on failure.
- Preserve existing rights notices; source selection is not a license grant. Runtime qualification and provenance checks precede declaring the starter selection ready to ship.
- Authenticate GitLab synchronization only from trusted main/recovery workflows using `FDROID_GITLAB_TOKEN`. Missing credentials fail visibly; never post discussion comments automatically.

## Review Focus

- A phone listing must import its own upstream metadata rather than the root TV Fastlane listing (Task 6 importer fixture).
- An old `auto_update=true` preference or sideloaded F-Droid APK cannot start an updater thread/request (Task 2 stub and artifact checks).
- Concurrent official/custom restore, category changes and skips cannot publish stale combined catalogs or delete an in-use generation (Tasks 3–4 race controls).
- Cancel/pause/process death around durable-pointer publication must retain either the previous complete library or the new complete library (Task 4 recovery fixtures).
- An older delayed release/recovery job cannot overwrite a newer GitLab branch or lose maintainer edits (Task 6 mocked API/concurrency controls).

## File and interface decisions

Use the existing native engine harness and framework instrumentation rather than adding a test framework. Keep native catalog work in `native-lib.cpp`, prewarm lifetime work in `preset_prewarm.*`, asset tooling in `tools/preset_distribution.py`, archive/storage logic in `OfficialPresetPack.java`, transfer/lifecycle work in `OfficialPresetDownload.java`, and dialogs in the distribution-selected `OfficialCollection.java` facade.

F-Droid builds expose one conditional AGP flavor: `fdroidTv` when touchscreen is false or `fdroidAndroid` when true. GitHub builds remain unflavored. This lets recipes select the correct upstream listing at `src/<flavor>/fastlane/metadata/android/en-US/` without changing existing GitHub task names. Shared F-Droid Java/manifest sources live under `app/src/fdroid/`; map the selected flavor to them. Version properties are `projectmReleaseVersion` and `projectmReleaseVersionCode`; reject conflicting nonempty environment/property values and invalid values. Retain supported CI suffixes for unpublished builds; the public release JSON contains a stable version only.

Archive schema 1 uses original source paths: `presets/<name>.milk`, `textures/<image>`, `presets.idx`, `preset-genres/**` and bundled notices. `manifest.json` lists sorted `{path, bytes, sha256}` file records and a content-derived `collection_id`; the manifest does not hash itself. The APK descriptor `official-pack.json` contains `schema_version`, `collection_id`, `archive_url`, `archive_sha256`, `compressed_bytes`, `expanded_bytes`, `preset_count` and `texture_count`. `expanded_bytes` includes the manifest. The archive filename is `cream-of-the-crop-<stable-version>.zip`; its bytes/identity do not change merely because the release tag changes. Commit `tools/preset-distribution/official-archive.json` with the content identity, ZIP SHA/sizes/counts and builder settings; F-Droid asset generation derives the descriptor from this verified lock rather than recompressing the collection and allowing host zlib differences to change APK bytes. Archive generation in release CI must match the lock or fail. Regenerate the lock when contributing collection files/notices change.

The starter selection has `schema_version: 1` and `status: candidate|qualified`, with its 20 source records and qualification-evidence link. Generated F-Droid assets include this small manifest as `starter-selection.json`; `--require-qualified` inspects that packaged status/count/hash record. This metadata belongs only to the starter tree, not the full archive, so qualification metadata does not change the full collection's identity.

Installed generations reuse the bounded custom ZIP extractor's generated storage paths. Add `official-presets.idx` rows `<storage-path>\t<canonical-name>\t<weight>` plus the original mood indexes and an installation marker. This keeps canonical names/weights while reusing safe extraction. Official data lives under `getNoBackupFilesDir()/official-presets`, with its own durable `current` pointer; user packs remain under `custom-presets`.

All commands below are planned validation commands, not results already observed. New commands/tests become runnable as their tasks land.
